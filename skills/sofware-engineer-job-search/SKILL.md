# Instructions

# Full Stack Software Engineer Job Search

## Purpose

Find high-quality Full Stack Software Engineer opportunities across the internet.

The goal is not simply to return job-board search pages. Find individual job postings, determine whether they are relevant to the candidate, remove duplicates and low-quality results, and return the best opportunities with direct application links.

---

## 1. Understand the Candidate

Before searching, identify as many of these constraints as are available:

- Experience level
- Preferred location
- Remote, hybrid, or onsite preference
- Countries where the candidate can legally work
- Required or preferred salary
- Preferred technologies
- Technologies the candidate does not want to use
- Startup versus established company preference
- Industries of interest
- Industries to avoid
- Full-time, contract, or freelance preference

Do not invent missing requirements.

If a constraint is unknown and does not prevent useful searching, search broadly and mention the assumption.

# 12. Inspect Every Candidate Job

Do not recommend a position based only on its title.

Open the posting and extract:

- Company
- Job title
- Location
- Remote policy
- Salary
- Equity if available
- Employment type
- Experience required
- Main technologies
- Required skills
- Preferred skills
- Responsibilities
- Company stage if available
- Posting date
- Application URL

Determine whether the listing is still active.

---

# 13. Detect Full-Stack Roles

A job should generally include work across at least two major application layers.

Strong full-stack indicators include combinations such as:

React + Node.js

React + Python

Next.js + PostgreSQL

Frontend + REST APIs

Frontend + backend services

UI + database

Product development + infrastructure

Do not classify a role as full stack merely because "full stack" appears in marketing copy.

---

# 14. Score Jobs

Score each job from 0 to 100.

Suggested weighting:

## Technology match — 30 points

Compare required technologies with candidate skills.

## Role match — 20 points

How closely does the actual work match full-stack/product engineering?

## Experience match — 15 points

Compare required years and seniority.

## Location / remote match — 15 points

Full points when the location arrangement matches the candidate's requirements.

## Compensation — 10 points

Compare against candidate expectations when salary is available.

Do not penalize a job simply because compensation is undisclosed. Mark it as unknown.

## Company preference — 5 points

Startup, scale-up, enterprise, etc.

## Freshness — 5 points

Prefer newly posted positions.

Example:

94 — Excellent Match

85 — Strong Match

74 — Good Match

61 — Possible Match

Below 50 — Normally exclude

---

# 15. Avoid False Negatives

Do not automatically reject a job because the candidate lacks one minor technology.

Separate requirements into:

CRITICAL

IMPORTANT

NICE TO HAVE

For example:

Candidate:
React + TypeScript + Node + PostgreSQL

Job:
React + TypeScript + Node + PostgreSQL + Redis

This is still a very strong match even if Redis is not listed on the candidate's résumé.

Likewise, treat wording variants as equivalent when appropriate:

Postgres = PostgreSQL

Node = Node.js = NodeJS

ReactJS = React.js = React

NextJS = Next.js

JS = JavaScript

TS = TypeScript

---

# 16. Red Flags

Lower the score or exclude jobs when:

- The listing appears expired
- The application URL is broken
- The same position has been reposted continuously for months
- The company cannot be verified
- The description is extremely vague
- Compensation appears suspicious
- The role requires payment from applicants
- It appears to be a training program disguised as employment
- It is primarily commission-based
- The title says full stack but responsibilities are unrelated
- Required work authorization clearly conflicts with the candidate
- Required location clearly conflicts with the candidate

Never claim that a company is fraudulent without strong evidence.

Instead label questionable listings:

Potential concern: [reason]

# 17. Deduplicate Results

The same job may appear on:

LinkedIn

Indeed

Wellfound

Google

Greenhouse

Lever

Company careers page

Keep only one entry.

Prefer URLs in this order:

1. Employer's official careers page
2. Employer's ATS application page
3. Wellfound / YC startup listing
4. LinkedIn
5. Major job board
6. Other aggregator

Consider jobs duplicates when they have the same:

Company + title + location

or clearly identical descriptions.

---

# 18. Search Company Websites

When a promising company is discovered:

1. Open the company's careers page.
2. Search engineering positions.
3. Look for related positions.
4. Check whether a newer version of the job exists.
5. Prefer the direct company application URL.

For example, finding one "Full Stack Engineer" position may reveal:

Senior Full Stack Engineer

Product Engineer

Software Engineer II

Founding Engineer

AI Product Engineer

These may be better matches.

---

# 19. Application Priority

Sort final results into:

## Apply First

Score 85–100.

Excellent technology, experience and location match.

## Strong Options

Score 70–84.

Good opportunities with minor mismatches.

## Stretch

Score 55–69.

Worth considering when the company or role is especially attractive.

Normally omit results below 55 unless specifically requested.

# 23. Search Quality Rules

DO:

- Search multiple title variants.
- Search multiple sites.
- Open individual job descriptions.
- Verify important requirements.
- Prefer direct company application URLs.
- Prefer recent jobs.
- Deduplicate results.
- Explain why each position matches.
- Identify missing requirements honestly.
- Look beyond jobs literally titled "Full Stack Engineer."
- Search company career pages.
- Search ATS-hosted pages.
- Check startups and remote-specific boards.

DO NOT:

- Return dozens of unfiltered links.
- Assume job-board snippets are accurate.
- Recommend expired positions.
- Invent salaries.
- Invent posting dates.
- Invent remote eligibility.
- Assume "remote" means worldwide.
- Assume technologies not mentioned in the description.
- Claim the candidate qualifies when a critical requirement is missing.
- Treat preferred requirements as mandatory.
- Return duplicate listings from several job boards.

---

# 24. Recommended Search Sequence

For a thorough search:

1. Search LinkedIn.
2. Search Indeed.
3. Search Wellfound.
4. Search YC Work at a Startup.
5. Search the current Hacker News Who Is Hiring thread.
6. Search We Work Remotely.
7. Search Remote OK.
8. Search Remote Rocketship.
9. Google-search Ashby job pages.
10. Google-search Greenhouse job pages.
11. Google-search Lever job pages.
12. Search company career pages discovered during the process.
13. Deduplicate.
14. Verify listings.
15. Score each position.
16. Return the best opportunities.

For a quick search, prioritize:

1. LinkedIn
2. Wellfound
3. Google / ATS pages
4. Company career pages

---

# 25. Core Principle

Optimize for:

**Relevant jobs the candidate can realistically apply to**

not:

**Maximum number of search results.**

Ten highly relevant, active positions with direct application links are more useful than 100 loosely related job-board results.
