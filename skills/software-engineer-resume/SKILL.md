# Software Engineer Resume Skill

## Purpose

Create and improve professional resumes for software engineers.

The resume should communicate:

- What the engineer built
- What technologies they used
- What problems they solved
- The scale or complexity of the work
- Their individual contribution
- The impact of their work
- Technical leadership when applicable

Prioritize concrete engineering accomplishments over generic responsibilities.

---

# Core Principles

## 1. Write accomplishments, not job descriptions

Avoid bullets such as:

> Responsible for developing React applications.

Prefer:

> Developed React and TypeScript applications supporting internal enterprise workflows.

Better when evidence is available:

> Built React and TypeScript applications used across multiple enterprise teams, creating reusable UI components that reduced duplicate frontend development.

Never invent metrics.

---

## 2. Never fabricate information

Do not invent:

- Revenue
- Percent improvements
- User counts
- Performance improvements
- Team sizes
- Technologies
- Job titles
- Clients
- Certifications
- Degrees
- Dates
- Leadership responsibilities

If useful information is missing, improve the wording using the facts available.

When metrics would significantly strengthen a bullet, suggest what type of metric the user could add.

Example:

> Reduced application load time by [X%] through JavaScript performance optimization and frontend architecture improvements.

Use placeholders only when explicitly helping the user identify information to fill in. Do not present placeholders as completed resume content unless requested.

---

# Resume Bullet Formula

Prefer this structure:

**Strong verb + technical contribution + context/technology + result**

Examples:

> Architected reusable React and TypeScript components for enterprise applications, improving consistency across internal development teams.

> Migrated legacy Angular applications to modern frontend architectures while maintaining existing business functionality.

> Designed a metadata search interface integrating AI-driven prediction capabilities for enterprise data discovery.

Not every bullet needs to follow exactly the same structure. Avoid making the resume sound mechanically generated.

- Modernized
- Optimized

- Established

- Improved

# Preserve Technical Accuracy

Do not exaggerate the candidate's ownership.

Distinguish carefully between:

- Developed
- Contributed to
- Designed
- Architected
- Led
- Managed
- Owned

For example, if the candidate says:

> contributed to AI prediction model engine

Do not rewrite this as:

> Architected an enterprise AI prediction engine.

Instead:

> Contributed to an AI-powered prediction engine supporting metadata search and enterprise data discovery.

Preserve the difference between contributing to a system and owning its architecture.

# Legacy Technologies

Do not hide older technologies when they demonstrate valuable experience.

Instead, emphasize modernization.

Example input:

> Migrated ASP.NET Web Forms application to Angular.js.

Possible rewrite:

> Modernized a legacy ASP.NET Web Forms application by migrating its frontend architecture to AngularJS.

Legacy technologies can demonstrate:

- Migration experience
- Enterprise experience
- Modernization expertise
- Long-term engineering experience
- Ability to work with complex existing systems

- Data platforms
- Cloud infrastructure
- Cross-team components
- Shared libraries
- B2B systems

Balance frontend and backend experience.

Highlight:

- Frontend frameworks
- Backend services
- APIs
- Databases
- Cloud infrastructure
- Authentication
- Distributed systems
- Testing
- Deployment
- CI/CD

# Senior / Lead Engineers

For senior engineers, emphasize progression beyond implementation.

Look for evidence of:

- Architecture
- Technical direction
- Mentorship
- Code reviews
- Engineering standards
- Cross-team collaboration
- Framework development
- Technical decision-making
- System design
- Modernization
- Developer productivity
- Reusable platforms
- Performance improvements

Example:

Input:

> Introduced google-style code standards/code reviews to UI team, lead others to write clean reusable UI code

Rewrite:

> Introduced Google-style coding standards and structured code reviews across the UI team, improving consistency and promoting reusable frontend architecture.

Do not claim management responsibility unless explicitly supported.

---

# AI Experience

AI-related experience is valuable but must be described accurately.

Distinguish between:

- Building ML models
- Building AI infrastructure
- Integrating AI models
- Building interfaces around AI systems
- Developing agent systems
- Using AI APIs
- Contributing to AI-enabled products

Do not convert AI-adjacent work into ML engineering.

Example:

> Developed frontend capabilities for an AI-powered enterprise metadata search platform.

is different from:

> Developed machine-learning models for enterprise search.

Preserve that distinction.

# ATS Optimization

Optimize naturally for Applicant Tracking Systems.

Include relevant terms from the candidate's actual experience.

Potential keywords:

Frontend:

React, TypeScript, JavaScript, Angular, Redux, HTML5, CSS, Sass, responsive design, component architecture

Backend:

Node.js, Java, Python, C#, REST API, microservices, SQL

Cloud:

AWS, Azure, cloud architecture, serverless, containers, Docker, Kubernetes

Engineering:

software architecture, system design, CI/CD, automated testing, performance optimization, code review, Agile

AI:

artificial intelligence, machine learning, LLM, generative AI, AI integration, vector search, semantic search

Only include keywords supported by the candidate's experience.

---

# Job Description Targeting

When a job description is provided:

1. Identify the primary role.
2. Extract the most important technical requirements.
3. Extract architecture and leadership requirements.
4. Compare those requirements against the candidate's experience.
5. Prioritize matching experience.
6. Incorporate terminology from the job posting where accurate.
7. Do not copy large portions of the job description.
8. Do not fabricate missing qualifications.

Prioritize high-value matches near the top of the resume.

## Company

- Achievement

- Achievement

For consulting positions involving major clients:

## Consulting Company
**Senior Software Engineer** | Dates

**Selected clients: AT&T, Amazon Web Services**

- Contributed to...
- Developed...
- Architected...
- Migrated...

Use whichever structure makes the relationship between employer and client clearest.

---

# Bullet Length

Prefer approximately 1–2 lines per bullet in a typical resume layout.

Usually use 3–6 bullets for important recent positions.

Older positions may use 2–4 bullets.

Do not force every detail from the source material into the final resume.

Prioritize relevance.

---

# Professional Summary

Keep summaries concise.

Usually 2–4 lines.

Include:

- Engineering level
- Years of experience if known
- Primary specialization
- Major technical strengths
- Relevant architecture/leadership experience

Example:

> Senior Software Engineer specializing in frontend and full-stack application development, with extensive experience building enterprise applications using React, TypeScript, JavaScript, and Angular. Strong background in UI architecture, application modernization, reusable component systems, and technical leadership across large-scale enterprise environments.

Do not use generic claims such as:

> Passionate results-driven rockstar developer who thrives in fast-paced environments.

---

# Skills Section

Group technologies logically.

Example:

**Languages:** JavaScript, TypeScript, C#, SQL  
**Frontend:** React, Redux, Angular, HTML5, CSS, Sass  
**Backend:** Node.js, ASP.NET  
**Cloud:** AWS  
**Engineering:** UI Architecture, System Design, Performance Optimization, Code Review, Application Modernization

Only include technologies actually supported by the candidate's experience.

Remove phrases such as:

- Hard worker
- Team player
- Self-starter
- Detail oriented
- Results-driven professional
- Excellent communication skills
- Works well independently
- Fast learner
- Passionate developer

Demonstrate these characteristics through accomplishments instead.

# Editing Existing Resume Content

When rewriting supplied bullets:

1. Preserve every important fact.
2. Correct grammar and spelling.
3. Replace weak verbs.
4. Remove unnecessary words.
5. Consolidate overlapping bullets.
6. Surface technical complexity.
7. Surface impact.
8. Preserve technical accuracy.
9. Improve ATS terminology.
10. Avoid exaggeration.

Example input:

> UI React/Redux/TypeScript development of internal applications

Rewrite:

> Developed internal enterprise applications using React, Redux, and TypeScript.

If more context supports it:

> Built React, Redux, and TypeScript applications supporting internal enterprise workflows and reusable UI patterns.

---

# Handling Rough Notes

Users may provide fragmented notes such as:

> angular/react/html/css/javascript  
> internal enterprise apps  
> desktop mobile  
> lots angular migrations

Interpret and rewrite these as professional resume content without requiring grammatically complete input.

Possible result:

> Developed enterprise desktop and mobile applications using Angular, React, JavaScript, HTML5, and CSS.

> Led and contributed to multiple Angular application migrations, modernizing legacy frontend codebases while preserving critical business functionality.

Use "led" only if leadership was explicitly stated or clearly established elsewhere in the supplied source material.

---

# Tone

Resume writing should be:

- Technical
- Concise
- Professional
- Confident
- Specific
- Credible
- Accomplishment-oriented

Avoid:

- Marketing hype
- Excessive adjectives
- Corporate buzzwords
- AI-sounding filler
- Repetitive sentence structures

---

# Resume Review Mode

When asked to review a resume, evaluate:

1. First-impression clarity
2. Target role alignment
3. Technical credibility
4. Strength of accomplishments
5. Metrics
6. Seniority signals
7. ATS compatibility
8. Repetition
9. Grammar
10. Formatting
11. Skills organization
12. Career progression
13. Unnecessary information
14. Missing high-value information

Identify the highest-impact improvements first.

---

# Output Modes

Adapt to the user's request.

## Rewrite Mode

Return polished replacement content.

## Review Mode

Explain problems and recommended improvements.

## ATS Mode

Optimize terminology and alignment against a supplied job description.

## Condense Mode

Reduce resume length while retaining the strongest accomplishments.

## Seniority Mode

Rewrite experience to better communicate senior or lead-level responsibilities without exaggerating ownership.

## Full Resume Mode

Produce:

1. Professional Summary
2. Technical Skills
3. Professional Experience
4. Selected Projects if relevant
5. Education
6. Certifications if relevant

---

# Final Quality Check

Before returning resume content, verify:

- No fabricated metrics
- No invented technologies
- No exaggerated ownership
- No spelling mistakes
- Consistent tense
- Consistent technology naming
- Strong verbs
- Minimal repetition
- Clear technical contribution
- Relevant impact
- ATS-readable terminology
- Appropriate seniority
- Concise bullets

The final resume should sound like it was written by an experienced software engineer, not by a generic resume generator.
